# 스크리닝 리포트 채점 루브릭

완성된 스크리닝 리포트 한 건을 읽고 **0–100점과 pass / revise / blocked 판정**을 남기는 기준.
`rubric_reference/`의 의료자문 실무 문서 3건에서 축을 끌어냈고, 실제 리포트 5건에 돌려 보정했다.

버전 `screening_rubric.v0.1` · 2026-08-21

---

## 1. 푸는 문제

리포트가 나왔는데 **잘 나온 건지 판단할 기준이 없었다.** 사람이 읽으면 "괜찮아 보인다"까지는 가지만,
그게 다음 버전보다 나아진 건지, 어느 부분이 부족한지, 두 사람이 같은 결론에 도달하는지가 남지 않는다.

루브릭이 만드는 것은 세 가지다.

- **비교 가능한 숫자** — 버전 간 개선을 측정할 수 있다
- **인용에 묶인 근거** — 모든 점수가 리포트 원문 인용을 달고 나온다. 인용 없는 점수는 스키마가 거부한다
- **고칠 지점** — 감점마다 무엇을 어떻게 바꾸라는 제안이 함께 남는다

## 2. 이것이 아닌 것

| | 이 루브릭 | 정답지 평가 |
|---|---|---|
| 비교 대상 | 리포트 ↔ 루브릭 | 리포트 ↔ 실제 손해사정서 |
| 답하는 질문 | 잘 만들어졌는가 | 맞았는가 |
| 지금 쓸 수 있나 | **예** | 아니오 (격리된 Unit 11 서비스 대기) |

채점자는 `source-cases/`·`data/ground_truth/`를 열지 않는다. 규칙이 아니라 역할의 구조적 성질이다.
이 루브릭은 리포트의 **정확성을 말하지 않는다.** 완성도를 말한다.

## 3. 채점자가 보는 것 — 그리고 그 대가

입력은 **리포트 마크다운 하나**다. 원본 의무기록도, 상위 단계 계약 파일도 보지 않는다.

그래서 채점자는 "리포트가 빠뜨린 사실"과 "사건 자료에 애초에 없던 사실"을 직접 구분할 수 없다.
입력을 넓혀서 풀지 않고, 다음 규칙으로 푼다.

## 4. 중심 규칙 — 침묵 대 명시

> 자료가 부족한 경우 '기왕력 없음'으로 단정하지 않고,
> '제공된 자료에서 확인되는 기왕력 없음'으로 표현한다.
> — 의료자문 핵심변수 문서, 표현 원칙

| 리포트의 상태 | 채점 |
|---|---|
| 값이 기재되어 있다 | 만점 |
| 값이 없고, **범위를 한정한 부재 선언**이 있다 | 만점 |
| 값이 없고, 아무 언급도 없다 | 감점 |
| 값이 없는데 **무한정 단정**했다 | 게이트 (판정 자체가 blocked) |

**모른다고 제대로 말한 리포트는 감점하지 않는다.** 벌점은 모르는 것을 아는 척한 쪽과,
모른다는 사실조차 말하지 않은 쪽으로 간다.

현행 리포트가 실제로 쓰는 문형을 그대로 인정한다 — `라우팅 우선순위상의 어떤 출처도 이 항목을
기재하지 않았습니다`, `기재가 없다는 점을 부정 소견으로 보지는 않습니다`, `확인 불가`.

## 5. 여섯 개 축

각 축 0–4점, 가중합 100점. 근거 문서가 축마다 다르다.

| 축 | 무엇을 보는가 | 근거 | 가중 |
|---|---|---|---|
| **A1** 구조 완결성 | 필요한 역할이 실제 내용으로 채워졌는가. 빈 껍데기·플레이스홀더는 없는가 | 리포트 템플릿 | 10 |
| **A2** 핵심변수 커버리지 | A등급 의료변수가 값 또는 명시적 부재로 처리됐는가 | 핵심변수 우선순위 | **25** |
| **A3** 근거 등급 | 주장이 A등급 문서(진단서·수술기록지·장해진단서)에 귀속되는가 | 의무기록 우선순위 | 15 |
| **A4** 유형·필요서류 정합 | 사건유형 판정이 사고경위와 맞고, 그 유형의 필수서류를 대조했는가 | 유형별 필요서류 | 20 |
| **A5** 쟁점·판단 실행가능성 | 읽는 사람이 다음에 무엇을 할지 나오는가. 손사/의사 라우팅이 맞는가 | 복합 | 15 |
| **A6** 내부 일관성 | 날짜·진단명·부위·기간이 섹션 간 어긋나지 않는가 | 복합 | 15 |

**A2가 가장 무겁다.** 리포트의 존재 이유가 의료변수를 우선순위대로 구조화하는 것이기 때문이다.
A등급으로 요구하는 것은 일곱 개뿐이다 — 주진단명, 진단서상 진단명, 주요 치료 유형, 수술 시행 여부,
최종 임상경과, 현재 치료상태, 환자 자가응답 기왕력. 나머지는 사건이 요구할 때만 본다.

**섹션 제목이 아니라 역할로 채점한다.** 저장소에 7·8·10섹션 세 가지 형태가 실재하므로,
제목 문자열에 루브릭을 묶으면 형태만 다른 정상 리포트가 0점이 난다.

## 6. 게이트 — 점수와 무관한 다섯 가지

하나라도 걸리면 총점이 몇 점이든 판정은 `blocked`. 게이트를 걸 때는 문제가 된 문장을 인용해야 한다.

| | 발동 조건 |
|---|---|
| **G1** | 금지표현 — 결정론적 검사 + 의미 패스 |
| **G2** | 자문의 판단영역 침범 — 장해율 산출, 증세고정 판단, 인과 단정 |
| **G3** | 무한정 부재 단정 — "기왕력 없음" |
| **G4** | 섹션 간 사실 모순을 리포트가 인지하지 못함 |
| **G5** | 사건유형과 청구담보가 양립 불가 |

G2가 중요하다. 기재된 장해율을 **옮겨 적는 것**은 정상이고, 리포트가 **스스로 산출하는 것**이 위반이다.

## 7. 점수와 판정

```
총점 = 100 × Σ적용가능(점수 ÷ 4 × 가중) ÷ Σ적용가능(가중)
```

사건이 애초에 관여하지 않는 축은 `적용 불가` + 사유로 기록하고 분모에서 뺀다.
축을 아예 빼는 것은 스키마가 거부한다 — 낮은 축을 조용히 없애는 경로를 막기 위해서다.

| 조건 | 판정 |
|---|---|
| 게이트 1개 이상 | `blocked` |
| 총점 80 이상 | `pass` |
| 그 외 | `revise` |

## 8. 실제 채점 결과

리포트 5건. 전부 계약 스키마 검증 통과.

| 리포트 | A1 | A2 | A3 | A4 | A5 | A6 | 총점 | 판정 |
|---|---|---|---|---|---|---|---|---|
| 705 (배상책임·법률의견 상반) | 4 | 4 | 3 | 4 | 4 | 3 | **92.5** | pass |
| 710 (개인보험·후유장해) | 3 | 4 | 4 | 4 | 4 | 3 | **93.8** | pass |
| 711 (교통사고·골반골절) | 4 | 3 | 3 | 4 | 4 | 3 | **86.2** | pass |
| 712 (711과 동일 파일) | 4 | 3 | 3 | 4 | 4 | 3 | **86.2** | pass |
| CASE_021 (형태 대조군) | 4 | 2 | 3 | 3 | 4 | 4 | **78.8** | revise |

게이트는 하나도 걸리지 않았다. 금지표현 검사는 5건 모두 `clean` — 실행해서 나온 값이다.

### 무엇을 잡았나

**710 — 영어 내부 문자열 노출** (A1 감점, high)
`the case holds no document of any kind this field routes to`가 §7에 6번 그대로 출력됐다.
부재 사유는 전달되지만, 손해사정사·의사에게 제출되는 한국어 문서다.

**711 — A등급 변수의 자리 이탈** (A2 감점)
환자 자가응답 기왕력이 구조화 영역(§4·§7) 어디에도 없고, §10 검토 포인트 본문의
`PMHx. n/s` 언급으로만 존재한다. 값을 아는 사람만 찾을 수 있는 위치다.

**705 — 근거 등급 미달** (A3 감점)
필요서류 체크리스트는 영상판독지를 '보유'로 기재하는데, 진단 근거는 경과기록지(B등급)의
`Xray>` 한 줄 요약에 의존한다. 의무기록 우선순위 문서의 '판독결과지 우선' 원칙에 미달.

**CASE_021 — 포괄 문장이 변수를 대신하지 못함** (A2 2점 → 유일한 `revise`)
"진단서·의무기록·영상 원본 자료는 사건 내 존재하지 않는다"는 한 문장으로 덮었지만,
그건 문서 종류의 부재이지 각 변수의 상태가 아니다. 주요 치료 유형·최종 임상경과·현재
치료상태·기왕력 네 항목이 값도 개별 부재 선언도 없이 비어 있다.

### 잘한 것도 잡힌다

710은 후유장해진단서의 운동범위 수치에서 **장해율을 도출하는 것을 명시적으로 거부**하고
의사 판단으로 넘겼다. 711은 맥브라이드 27%와 AMA 30%를 **병기한 채 병합하지 않았다.**
둘 다 G2를 피한 정확한 처리이고, 루브릭은 이것을 감점이 아니라 정상으로 읽는다.

## 9. 이 실행이 말해주지 않는 것

발표에서 넘어가면 안 되는 세 가지.

**A5는 아무것도 변별하지 못했다.** 다섯 건 전부 4점. 모든 리포트가 쟁점을 손사·의사·법률전문가로
라우팅하고 구체적 확인 사항을 지정한다. 이 코퍼스의 성질이지 축이 불필요하다는 증거는 아니지만,
현재 15점의 가중치가 전혀 움직이지 않는다. 다음 코퍼스에서도 같으면 조정 대상.

**711/712 결정론 검증은 결론이 없다.** 두 파일은 바이트가 같고 점수도 같지만, 같은 세션에서
두 번째가 첫 번째 판단을 재사용했다. **채점자 재현성의 증거가 아니다.** 진짜 검증은
컨텍스트를 공유하지 않는 독립 2회 채점이 필요하다.

**사람 채점과의 일치는 측정하지 않았다.** 이 루브릭으로 사람이 채점한 적이 아직 없다.

### 앵커 세 곳이 애매했다 — 조용히 정하지 않고 기록했다

1. **미번역 내부 문자열의 A1 레벨** — 내용은 맞고 언어만 틀린 경우를 앵커가 명시하지 않는다
2. **A6 최하위와 게이트 G4의 경계** — 서로 다른 두 필드의 긴장을 어느 쪽으로 볼지
3. **질병 청구의 A4 적용성** — 유형별 필요서류 문서의 4개 유형은 상해·배상 계열 전제다

## 10. 쓰는 법

```bash
# 게이트 결정론적 바닥
python tools/dao.py check-forbidden-expressions <리포트.md>

# 결과 검증
python tools/validate_output.py rubric_test/results/*.json
```

채점은 `screening-rubric` 에이전트가 수행한다. 사건 안에서는 DAO의 `write-contract`로,
`outputs/` 밖의 단독 리포트는 리포트 옆에 쓰고 `validate_output.py`로 검증한다.

### 산출물

| 파일 | 내용 |
|---|---|
| `templates/rubric-screening-report.md` | 루브릭 본문 — 축 정의, 0–4 앵커, 게이트, N/A 규칙 |
| `schemas/screening_rubric_result.schema.json` | 결과 계약 — 인용 없는 점수, 사유 없는 N/A를 거부 |
| `.claude/agents/screening-rubric.md` | 채점 에이전트 정의 |
| `rubric_test/results/*.json` | 채점 결과 5건 |
| `docs/run-notes/2026-08-21-screening-rubric-calibration.md` | 보정 실행 기록 |

### 덧붙임 — 실행 중 발견한 결함 1건

`tools/dao.py`가 Python 3.14에서 **아예 기동하지 않았다.** argparse가 help 문자열을 검증하는데
`--pages` 도움말의 `81% of the`가 `%o` 변환으로 파싱돼, 서브커맨드 전체가 죽는 상태였다.
루브릭의 G1 검사를 실행하다 드러났고, escape 한 글자로 수정했다.
