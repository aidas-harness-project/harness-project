## Defects this run found

Four, none of which any test had caught, all fixed on the branch:

* **Resolving a bundle's P8 disagreement classified it.** `--bundle-ocr`
  withheld the `document_type`; `resolve-disagreement` then reached the
  shared tail without the flag and labelled the whole 19-page bundle
  `diagnosis_certificate` from its first page.
* **No way to classify without re-reading.** The only entry point was
  `run`, which begins by OCR'ing. Using it on the children destroyed the
  inherited P8 history of DOC_006-013, which had to be rebuilt from the
  parent. `classify-only` and a refusal guard now exist — and the spec
  that said "classify the children as usual" (meaning `run`) was the
  reason I did it.
* **The split did not redistribute the bundle's redaction.** Children had
  no redacted text, so each would have been redacted again, and the
  manifest's `redacted_text_path` — which chunking reads — stayed null.
* **Classification read raw page text.** It followed `ocr_result`'s
  `text_path`, which points at `page_NNN.md`: the pre-redaction data the
  DAO guards behind a one-shot capability, reached by a path that never
  goes through the DAO. It now prefers the redacted layer and records
  `classification_text_source` either way, so a raw read is visible
  rather than silent.

Two of those four were found by the case owner reading the run's output
state, not by me and not by the suite.
