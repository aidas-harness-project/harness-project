# CASE_908 — RUN_20260805_001 — stage-inversion verification

Branch: `feature/stage-inversion`. Purpose: verify, on real data and with a
real provider, that boundaries can be derived from already-processed text
rather than from contact-sheet vision — the change that lets the
deterministic path reach a scan at all.

## Case

`CASE_908` is a fork of `CASE_907` (`fork_case.py --include-raw`, ground
truth deliberately not copied, so D1 isolation holds). Target: `DOC_005`,
a 19-page medical bundle that is a **genuine scan** — zero embedded text
characters on all 19 pages, so `text_anchor_boundaries()` (which reads the
PDF's own layer) returns None for it and every earlier run fell through to
the vision path.

Input to every measurement below:
`data/processed/CASE_908/DOC_005/redacted_text.md`, split on the
`<<<PAGE page=N>>>` markers checkpoint 2 embeds. **No OCR was run and no
PDF or image was read** — this is text that was already OCR'd and already
redacted.

Baseline: the human-approved split recorded in
`outputs/CASE_907/document_manifest.json` (DOC_214–DOC_224
`source_page_start`/`source_page_end`), boundaries
`{1,2,3,4,6,7,8,9,16,17,18}`.

## LLM tier — real provider

Provider: `claude-cli` (`ClaudeCliProvider`, `--safe-mode`). 5 of 19 pages
reached the judge (26%); the other 74% were settled deterministically and
cost nothing.

| page | first line | verdict | confidence | correct |
|---|---|---|---|---|
| p5 | `06` / `Page` / `병리조직 : ( 유 ☐ 무 ☐ )` | new document | **0.62** | no |
| p6 | `REPORT` (MR HAND reading) | new document | 0.93 | yes |
| p7 | `REPORT` (Right Wrist AP reading) | new document | 0.85 | yes |
| p18 | `[자료 13] 위자료 산정기준표` | new document | 0.97 | yes |
| p19 | `- 2007년도부터 서울 소재 지방법원에서…` | continuation | 0.96 | yes |

Result: **precision 0.9167, recall 1.0000, F1 0.9565** — one false
positive, no misses. Against the oracle-stub ceiling (1.0000/1.0000) the
gap is exactly p5.

The tier answered correctly on all three cases it was built for: it
separated p6 from p7 despite both being headed `REPORT` (different
studies, each with its own patient block and Conclusion), recognised p18
as a new document with no form title, and read p19 as its continuation.

### p5 — an input limitation, not a misjudgement

Reviewed by the case owner (pyun): p5 genuinely continues p4's 수술 기록,
but the surgical narrative is **not present in the source material** —
this corpus was supplied already stripped of personal information, so the
body text that would make the continuation visible never reached the
pipeline at all. It is not that our redaction removed it. The model was
reading what exists, and marked it with the only low confidence in the
run (0.62 against 0.85–0.97 elsewhere).

What this does and does not establish: it does NOT show that redaction
scope moves segmentation accuracy — that would need a case where our own
redaction removed body evidence, which this is not. What it does show is
that the LLM tier degrades gracefully on thin input: it reached for the
one page with the least evidence and flagged its own uncertainty rather
than answering confidently and wrongly.

The distinction still matters for later, when real PII-bearing documents
are processed: the deterministic tier depends on document TITLES
(verified surviving redaction across CASE_112's 217 split children) while
the LLM tier depends on BODY text, so the two tiers do not have the same
sensitivity to whatever a future redactor removes. That is a hypothesis
to test at that point, not something this run measured.

Not acted on this run. A confidence threshold that routes low-confidence
verdicts into `undecided_pages()` (so the human approval gate sees them)
is the obvious follow-up, but 5 judged pages is not enough to set a
number against.

## Defect found while running: multi-line prompts silently truncated

The first real-provider attempt returned zero usable verdicts. Cause was
mine, not the tier's: I passed `HARNESS_CLAUDE_COMMAND` pointing at the
npm `claude.cmd` shim. `subprocess.run([...], shell=False)` on a `.cmd`
still routes through `cmd.exe /c`, whose batch-argument parsing truncates
a multi-line prompt at the first blank line — the exact failure
`_resolve_claude_cli_command()` exists to prevent by resolving to
`claude.exe` directly. Specifying the shim explicitly overrode that
protection.

Two things worth recording:

* The model diagnosed it correctly — it replied that the prompt was cut
  off mid-sentence rather than guessing at an answer.
* `_judge_boundary()` rejected that reply (not JSON) and the tier fell
  back to splitting and flagging, exactly as designed. A truncated prompt
  produced no fabricated boundaries. This is the fail-safe path working
  on a real failure rather than a simulated one.

Removing the override resolved the command to
`…/node_modules/@anthropic-ai/claude-code/bin/claude.exe` and multi-line
prompts worked immediately.
